一、整体说明（完全对齐老师验收要求）
1. 本系统全程不做模型训练、不做微调、不做数据标注，全部使用开源现成大模型，符合老师MVP验收建议。
2. 系统存在两套独立AI能力（共用本地Ollama大模型，仅Prompt与业务逻辑不同）：
•	AI能力1：自动生成采集脚本（XPath/CSS） —— 归属成员A
•	AI能力2：网页数据清洗 + 结构化信息提取 —— 归属成员B
3. 基础架构：爬虫抓取 → Crawl4AI通用清洗 → 大模型AI结构化清洗 → 后端入库 → 前端展示
4. 所有AI均为本地私有化部署（Ollama），数据不出内网，无公网API依赖。
二、核心角色定位（最终定稿）
成员A：爬虫开发 + 采集任务 + 【脚本生成AI】负责人
核心定位：负责“怎么抓、抓哪里、自动生成抓取规则”
AI权责：负责「生成采集脚本的AI」整套调用逻辑
1. 爬虫基础功能
•	网页请求、动态渲染、延时加载、超时控制、缓存控制
•	BloomFilter链接去重、死链过滤、并发控制
•	图片下载、MinIO对象存储上传
•	Celery异步任务队列、任务状态管理、预览/正式任务区分
2. Crawl4AI 部署与调用（专属负责）
•	统一环境部署 Crawl4AI、版本维护、依赖管理
•	完成 HTML 降噪、正文提取、HTML 转标准 Markdown
•	输出干净 Markdown 文本，交付给成员B做二次AI清洗
3. 成员A专属AI能力（P2迭代功能）
用途：预览采集时自动生成 XPath/CSS 采集脚本
•	编写、维护 AI脚本生成调用代码（对接本地Ollama）
•	设计脚本生成专用 Prompt、HTML骨架精简逻辑
•	AI生成脚本后自动回填前端高级代码框
•	执行AI生成的采集规则，完成精准字段抓取
•	处理AI调用超时、失败、无效规则等异常兜底
4. 任务流程控制
•	预览采集：抓取10条样本、临时内存存储、不入库
•	全量采集：确认后批量抓取、正式任务归档入库

成员B：数据处理 + 格式规整 + 【数据清洗/提取AI】负责人
核心定位：负责“抓到数据后怎么整理、怎么提取有效信息”
AI权责：负责「数据清洗、结构化提取的AI」整套调用逻辑
重要约束：全程无训练、无微调，仅调用现成本地大模型 + 规则兜底
1. 本地大模型部署（B专属运维）
•	Ollama本地部署开源大模型（Qwen2/DeepSeek等）
•	模型常驻服务、端口维护、进程监控
•	无需API Key、纯本地离线推理
2. AI智能清洗与结构化提取（核心工作）
接收A输出的Markdown，调用本地大模型完成：
•	教师姓名、职称、院系、研究方向自动提取
•	个人简介精简、冗余内容剔除
•	LaTeX公式、复杂表格、参考文献规整修复
•	文本去重、段落规整、脏内容剔除
3. 规则兜底校验（保障稳定性）
针对AI可能出现的幻觉，B增加纯规则兜底：
•	正则校验：手机号、邮箱、编号
•	教育词典匹配：职称、院系关键词
•	空值校验、脏数据标记、待人工清洗标记
4. 输出成品数据
输出：结构化JSON字段 + 格式化标准Markdown，交付后端入库与前端展示。

核心定位：所有用户可视、可操作功能全部落地
•	左侧导航、模板详情页、配置面板完整实现

三、两套AI严格区分（最终核心边界）
1. 成员A 的 AI：只管「生成抓取规则」
•	输入：URL + 页面结构 + 用户提取指令
•	输出：XPath / CSS 采集脚本
•	用途：告诉爬虫「去哪里抓数据」
2. 成员B 的 AI：只管「清洗提取数据」
•	输入：Crawl4AI输出的Markdown全文
•	输出：结构化、干净、规整的业务数据
•	用途：把抓到的杂乱网页，变成可用知识库数据
共用硬件、共用Ollama服务、共用开源模型，但是：Prompt、代码、业务、负责人完全独立，互不干涉。
四、全链路标准数据流（最终固定）
用户操作(D) → 后端调度(C) → A：AI生成脚本 + 爬虫抓取 + Crawl4AI基础清洗 → B：AI智能清洗 + 规则校验结构化 → 数据入库(C) → 前端展示(D)
