### 2.3 Worker 模式代码审查

Worker 模式的 API 调用链路逐项核查通过：

| 步骤 | 接口 | 状态 |
|------|------|------|
| 1. 健康检查 | `GET /api/health/` | `check_health()` 已实现，Worker 启动时调用 |
| 2. 获取配置 | `GET /api/crawler/config/db/` | `get_config()` 已实现，每 10 轮刷新一次 |
| 3. 拉取待爬种子 | `GET /api/seeds/pending/` | `get_pending_seeds()` 已实现，`results→seeds` 映射正确 |
| 4. 标记爬取中 | `POST /api/seeds/status/` | `update_seed_status(url, "crawling")` 已调用 |
| 5. 创建任务 | `POST /api/crawl/start/` | `start_crawl_task(task_type="formal", user_prompt=...)` 已传递 |
| 6. 页面快照上报 | `POST /api/pagesnapshot/` | `save_page_snapshot(task_id, task_type, user_prompt, raw_html)` V2 字段完整 |
| 7. 任务结果上报 | `POST /api/tasks/{id}/result/` | `report_task_result(task_id, "completed"/"failed", ...)` 已实现 |
| 8. 标记完成/失败 | `POST /api/seeds/status/` | `update_seed_status(url, "success"/"failed")` 正常/异常路径均覆盖 |

V2 字段贯穿验证：`user_prompt` 和 `task_type=formal` 从 `_run_api_worker → start_crawl_task → _run_bfs_crawl → _worker → process_page → save_page_snapshot` 全链路完整传递。

### 2.4 异常路径覆盖

- HTTP 403/429/503 状态码 → `analyze_anti_crawl()` 检测反爬信号，结果写入 `result["anti_crawl"]`
- 抓取异常 → `update_seed_status(url, "failed")` + `report_task_result(task_id, "failed", error_message=...)` 双重上报
- 后端 5xx → `_request` 指数退避重试（最多 3 次）
- 优雅关闭 → SIGINT/SIGTERM 信号处理，完成当前批次后退出并打印累计统计

此命令会走完整的 API 链路（start_crawl_task → 上报 pagesnapshot → report_task_result），但只抓取 1 个种子、深度 1 层，适合快速确认接口对接无误。
