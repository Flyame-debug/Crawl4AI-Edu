**日期**：2026-06-15

**任务**：修复 AI 脚本生成模块的 Prompt 质量与超时处理

---

## 修复背景

上一轮测试发现 qwen2:7b 模型在生成 XPath/CSS 规则时存在三个问题：将 CSS class 误识别为 HTML 属性（如 `@name` 替代 `@class='name'`）、CSS 输出包含 `::text` 非标准后缀、XPath 存在语法错误（如 `@@email`）。本次修复从 Prompt 模板、超时处理和 HTML 摘要格式三个层面进行了优化。

---

## 修改内容

### 1.1 Prompt 模板优化（script_generation.txt）

新增"摘要格式说明"章节，明确 `[class='name']` 标记对应于原始 HTML 的 `class="name"` 属性，并在输出格式章节增加以下约束：CSS 只输出元素选择器，禁止 `::text`、`::attr()` 等后缀；XPath 必须使用 `@class='xxx'` 或 `contains(@class,'xxx')` 进行匹配，明确禁止 `@name`、`@email`、`@title` 等不存在的属性。示例部分新增两个与当前摘要格式一致的输入输出对，其中一个展示 `contains(@class,'xxx')` 处理多类名的正确用法。

### 1.2 Ollama 超时处理（ollama_client.py）

将 `Timeout` 异常的捕获逻辑从 `raise`（抛出异常导致调用方崩溃）改为返回空字符串并记录 `logging.warning`，提示"将使用兜底规则"。上层 `generate_extraction_rules` 在收到空响应时自动降级为关键词兜底规则，确保系统在模型冷启动或响应过慢时始终可用。同步更新了函数 docstring，移除 Raises 段落，明确所有异常场景均返回空字符串。

### 1.3 HTML 简化格式改进（generate_rules.py）

将 `_simplify_html` 中 class 属性的输出格式从 `span.name` 改为 `span[class='name']`。原格式 `span.name` 对模型存在歧义：模型可能将其理解为 `<span name="...">`（HTML name 属性）而非 `<span class="name">`（CSS class）。新格式直接使用 `[class='...']` 标记，与 XPath 的 `@class` 语法一致，消除了这一歧义。

## 验收结果

运行 `python -m script_generator.generate_rules` 两次测试均达到验收标准：

测试 1（提取所有教师姓名）：
- XPath: `//span[@class='name']/text()` — 正确使用 `@class` 匹配
- CSS: `div.teacher span.name` — 无 `::text` 后缀
- source: `ai`，confidence: 0.95

测试 2（提取所有教师的姓名和邮箱）：
- XPath: `//span[@class='name']/text() | //span[@class='email']/text()` — 语法正确
- CSS: `(div.teacher span.name, div.teacher span.email)` — 无 `::text` 后缀
- source: `ai`，confidence: 0.95

HTML 简化格式输出示例：`<div[class='teacher']><span[class='name'] = "张三">`，格式清晰无歧义。

超时降级验证通过：冷启动时测试 1 超时，正确降级到兜底规则并输出 `source: "fallback"`，系统未崩溃。
