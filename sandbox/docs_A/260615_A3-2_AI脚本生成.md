## 任务概述

本次迭代实现了 Crawl4AI 系统的 AI 脚本生成能力——根据用户自然语言指令和目标页面 HTML，自动生成 XPath/CSS 采集规则。整个模块由三个子任务构成：Ollama 本地客户端封装（N5）、脚本生成 Prompt 模板设计（N6）、以及核心规则生成函数（N7）。模块可在 Ollama 服务不可用时自动降级为关键词兜底规则，保证系统始终可用。

---

## 子任务完成情况

### N5：本地 Ollama 连接测试

**文件**：`sandbox/ai_client/ollama_client.py`

实现了 `ask_ollama(prompt, model="qwen2:7b") -> str` 同步函数，通过 `requests` 库调用 Ollama 的 `POST /api/generate` 接口。核心设计要点：

- **超时处理**：30 秒请求超时，避免调用方无限等待。
- **错误分层**：区分连接错误（返回空字符串并打印友好提示）、超时（抛出异常供上层决策）、HTTP 错误（返回空字符串并记录日志）。
- **空响应检测**：当 Ollama 返回 `response` 字段为空时，记录 warning 日志并返回空字符串，触发上层兜底逻辑。
- **测试块**：`if __name__ == "__main__"` 中发送问候语 prompt，打印响应或提示启动 Ollama。

**验收结果**：Ollama 服务不可用时，`ask_ollama("你好，请用一句话介绍你自己。")` 打印友好错误提示并返回空字符串，行为符合预期。`requests` 版本 2.32.3 已存在于当前环境，无需新增依赖。

### N6：设计脚本生成 Prompt

**文件**：`sandbox/ai_client/prompts/script_generation.txt`

编写了结构化的系统提示模板，包含以下组成部分：

- **角色定位**：明确定义 AI 为"网页采集规则生成专家"。
- **输入格式说明**：清晰描述用户指令和页面 DOM 树摘要两个输入源，并给出了格式示例。
- **输出格式规范**：严格 JSON，包含 `xpath`、`css`、`confidence` 三个字段，附带字段说明。
- **完整示例**：提供了一个"提取教师姓名"的 faculty 页面输入示例及对应正确输出（XPath 使用 `@class` 属性匹配）。
- **错误处理指引**：当无法匹配时输出 `{"error": "原因"}`。
- **约束条款**：仅输出 JSON（不带 markdown 代码块标记）、优先 class 匹配、避免绝对位置依赖。

**验收结果**：模板内容完整，示例合理，约束清晰。与 N7 配合使用时，模板能正确加载并通过 `str.format` 风格的变量注入（instruction 和 HTML 摘要拼接在模板末尾）。

### N7：实现 AI 脚本生成函数

**文件**：`sandbox/script_generator/generate_rules.py`

实现了 `generate_extraction_rules(html, instruction) -> dict` 核心函数，遵循"简化→推理→兜底"三步流水线：

**步骤 1 — HTML 简化（`_simplify_html`）**：
使用 BeautifulSoup 解析 HTML，递归遍历 `<body>` 内所有元素，仅保留含直接文本内容或 `class`/`id` 属性的元素，构建缩进树形摘要。摘要上限 3000 字符，超出自动截断并标注。该设计滤除了大量无意义的 `<script>`、`<style>` 和无文本容器，大幅缩减 prompt 开销。

**步骤 2 — Prompt 拼装与推理**：
加载 N6 的 Prompt 模板（`script_generation.txt`），将用户 instruction 和 HTML 摘要拼接在末尾，调用 `ask_ollama` 获取 AI 响应。

**步骤 3 — JSON 解析与兜底（`_extract_json` + `_fallback_rules`）**：
JSON 解析采用三级策略：直接 `json.loads` → 正则提取第一个 `{...}` 块 → 去除 markdown 代码围栏后重试。任一策略成功即返回解析结果；全部失败则触发兜底规则。

**兜底规则（`_fallback_rules`）**：
基于中文关键词映射表（覆盖"姓名""职称""电话""邮箱""部门""研究方向""简介""图片""链接"等 14 个常见采集目标），将 instruction 中包含的关键词转换为 `contains(@class, ...)` 模式的 XPath 和 CSS 选择器。若完全不匹配，返回通用全文本提取规则。兜底规则的 `confidence` 固定为 0.3，`source` 标记为 `"fallback"` 以便区分。

**测试块**：`if __name__ == "__main__"` 中使用一个包含 2 位教师（张三、李四）信息的 `teacher-list` HTML 片段，分别测试"提取姓名"和"提取姓名+邮箱"两个指令，并打印 HTML 简化摘要。Ollama 不可用时自动降级为兜底规则。

**验收结果**：

测试 1（指令"提取所有教师姓名"）：
```json
{
  "xpath": "//*[contains(@class,'name')]/text()",
  "css": "[class*='name']",
  "confidence": 0.3,
  "source": "fallback"
}
```

测试 2（指令"提取所有教师的姓名和邮箱"）：
```json
{
  "xpath": "//*[contains(@class,'name')]/text() | //*[contains(@class,'email') or contains(@class,'mail')]/text()",
  "css": "[class*='name'], [class*='email'],[class*='mail']",
  "confidence": 0.3,
  "source": "fallback"
}
```

HTML 简化输出保留了 `<div.teacher>` 及其子元素的树结构，仅包含 class 属性和文本内容，压缩效果显著（原始 HTML 443 字符 → 摘要约 380 字符，含缩进格式）。

对于包含 `<div class="teacher"><span class="name">张三</span></div>` 的页面，指令"提取姓名"，生成的规则 `//*[contains(@class,'name')]/text()` 语义正确——使用 `contains()` 增强了容错性。
