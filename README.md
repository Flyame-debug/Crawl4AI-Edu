# 教育知识库采集系统项目总体指导

## 1. 项目概述
本项目基于开源爬虫框架 Crawl4AI（Apache 2.0）进行 Fork 扩展，构建一个 面向高校教育领域的智能网页抓取与数据提取系统。系统核心目标是自动从高校公开网站（师资、课程、科研成果等页面）采集多模态数据，清洗转换为结构化 Markdown 与知识库，并支持大模型训练数据集的持续更新。

最终交付物是一个 Web 应用系统，包含：后台异步爬虫引擎、AI 内容解析服务、REST API 数据服务、Vue 前端管理看板。

## 2. 技术栈与约束
前端：Vue 3 + Element Plus + ECharts + jsPlumb

后端：Django + Django REST Framework

异步任务：Celery（broker/backend 用 Redis）

数据库：PostgreSQL / MySQL（建议 PostgreSQL）

对象存储：MinIO（用于图片等二进制文件）

AI 模型：HuggingFace Transformers（BERT-NER 微调）、LangChain（提示词工程）

爬虫引擎：aiohttp + Playwright（按需动态渲染）+ Scrapy（仅用 LinkExtractor）

部署：不使用 Docker，但必须在指定conda 虚拟环境（如crawlai-edu）中运行

版本控制：GitHub

## 4. 功能模块需求清单（按模块）

### 4.1 网页内容转换
目标：将抓取的原始 HTML 转化为高质量 Markdown，保留学术特征。

- 自动识别网页主体区域，剔除导航、侧边栏、页脚等噪音（基于 readability-lxml + BeautifulSoup 清洗）。
- 支持将 HTML 表格转换为 Markdown 表格，复杂合并单元格表格允许保留 HTML 片段。
- 数学公式（LaTeX/MathML）原样保留，无法解析的公式图片需记录为标记。
- 参考文献序号自动聚合至文末。
- 输出内容需校验质量（长度、必填字段非空），不达标数据标记为“待清洗”。

### 4.2 网页库管理
目标：持久化存储抓取内容，支持版本追溯和分类检索。

- 存储网页快照（原始 HTML、清洗后 Markdown、元数据）到数据库。
- 图片等静态资源存储到 MinIO，数据库仅记录访问 URL。
- 增量更新：对比内容哈希，内容未变化不产生新快照，变化时记录版本。
- 自动分类：根据 URL 路径关键词（如 teacher, course, research）自动打标签（师资/课程/科研/新闻）。
- 提供 REST API 供前端查询、筛选、手动修改分类。
- 前端管理界面可浏览网页列表、查看详情、按标签筛选。

### 4.3 种子 URL 维护
目标：管理待爬取链接，自动发现新链接，避免死链和重复抓取。

- 支持手动添加/导入种子 URL，记录学校名称、所属分类、是否需要渲染等属性。
- 从已抓取页面自动提取同域名链接，通过白名单正则过滤（保留教育相关路径）。
- 全局 URL 去重（布隆过滤器 + Redis 持久化）。
- 死链检测：抓取前 HEAD 请求验证，连续失败阈值后标记失效。
- 每个目标高校维护一个 JSON 配置文件（域名、白名单规则、渲染需求、编码等），作为“高校特征库”。

### 4.4 AI 提示词工程管理
目标：通过自然语言描述爬取需求，自动生成提取规则。

- 前端提供界面输入需求（如“提取本页的教师姓名和职称”），后端调用大模型生成 XPath/CSS 选择器。
- 系统内置 Few-Shot 示例（教育网页片段+对应选择器），提升生成准确率。
- HTML 骨架化处理：仅保留标签结构与 class/id，去除文本，以缩短 Token 长度。
- 前端可拖拽编排爬取流程（打开页面→提取字段→翻页），使用 jsPlumb 实现。
- 已验证成功的 Prompt 存储于数据库，供后续复用。

### 4.5 页面内容抓取
目标：稳定、礼貌地抓取高校公开页面，提取文本、表格、图片。

- 基于 aiohttp 的异步请求引擎，支持随机 User-Agent 和请求间隔（1–3秒）。
- 对需要 JavaScript 渲染的页面（高校特征库标记），切换到 Playwright 无头浏览器抓取。
- 同一域名并发数限制（如不超过3），避免对学校服务器造成压力。
- 提取结构化字段（教师姓名、职称、研究方向等）依赖预先配置的 CSS 选择器规则。
- 表格使用 pandas 提取，图片下载至 MinIO。
- 非结构化文本兜底：正则提取邮箱/电话，jieba 分词 + 职称词典匹配。

### 4.6 数据提取策略 AI 分析
目标：自动识别页面模板，匹配最佳提取规则。

- 计算页面 DOM 结构指纹（simhash），容忍微小结构变化。
- 对大量页面指纹聚类（DBSCAN），自动发现模板类型。
- 为每类模板配置提取规则集（JSON），新页面指纹匹配后自动应用。
- 提取后完整性检查（教师姓名必填等），连续失败触发告警并暂停该高校任务。

### 4.7 行业特征训练
目标：微调教育领域 NER 模型，提升非结构化文本提取精度。

- 使用 doccano 搭建标注环境，定义实体类别（至少覆盖：姓名、职称、研究方向）。
- 标注不少于200条教育网页文本，导出 BIO 格式。
- 基于 HuggingFace Transformers 微调 bert-base-chinese 进行 Token 分类。
- 导出 ONNX 模型供生产环境集成。
- 推理时优先使用微调模型，失败自动降级到规则提取。

### 4.8 并发管理与安全协议
目标：保证爬虫稳定运行，遵守法律法规和网站规则。

- 所有抓取任务通过 Celery 异步执行，支持超时中断（如 5 分钟）和自动重试（3次，指数退避）。
- 任务队列状态通过 Flower 面板监控。
- 严格遵守 robots.txt：抓取前解析并过滤禁止路径。
- 遵守 Crawl-delay 指令，默认延迟 1–3 秒。
- 禁止抓取任何需登录或涉及隐私的页面。

### 4.9 可视化监控
目标：实时展示系统状态与数据质量。

- 后端提供数据统计 API：累计抓取量、分类分布、字段完整率、任务成功率等。
- 前端仪表盘使用 ECharts 绘制饼图、折线图，每5秒轮询更新。
- 当数据完整率 < 阈值或任务失败率过高时，前端高亮告警。
- 错误日志集中记录，并可通过 API 供前端查看。

## 5. 关键约定与注意事项
配置文件与密钥（如数据库密码、MinIO凭证、API Key）必须放在 .env 或 settings_local.py，绝不可提交到 Git。

仅爬取公开页面，遵守 robots.txt，不访问登录墙后内容。

每个高校的特征配置单独保存为一个 JSON 文件，存放在 configs/sites/ 目录下，方便维护和扩展。

前后端通信统一采用 REST API，所有接口需在 Django REST Framework 中注册，并在前端通过 Axios 调用。

数据质量是核心：宁可少抓，不可脏存。所有进入数据库的记录必须通过基本完整性检查。

代码规范：后端遵循 PEP8，前端使用 ESLint + Prettier
